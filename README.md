# English Time! (MVP)

6歳児向けの、音声だけで完結する英会話練習アプリの最小構成です。
子どもは OpenAI / ChatGPT に一切触れず、常に自分のバックエンド（この Next.js アプリの
API Route）経由でのみ会話します。

## できること / できないこと（MVP時点）

- できる: マイクで話す → 文字起こし → 固定のシステムプロンプトで応答生成 → 音声で再生、を繰り返す
- できる: 入力・出力の両方をモデレーションし、危険/範囲外の発言はやんわり英会話に誘導
- できる: 1日あたりの簡易利用時間の上限（メモリ上のみ、再起動でリセット）
- まだ: 保護者ダッシュボード、フレーズ集計、音声/会話ログの永続化（意図的に未実装）

## セットアップ

```bash
cp .env.local.example .env.local
# .env.local に OPENAI_API_KEY を設定
npm install
npm run dev
```

`http://localhost:3000` を開き、STARTボタンを押しっぱなしにして話し、離すと送信されます。

## 重要な設計判断（なぜこうしたか）

1. **ブラウザは OpenAI と直接通信しません。** OpenAI の Realtime API を
   ブラウザから WebRTC で直接叩く構成（エフェメラルトークン方式）も検討しましたが、
   その構成では接続後にクライアント側から `session.update` イベントを送ることで
   システムプロンプト（instructions）を上書きできてしまう、というのが現在の仕様です。
   6歳児本人がそれをやることはまずありませんが、「子どもがChatGPT自体に触れない」
   という要件を技術的に保証するには不十分と判断し、MVPでは音声認識→テキスト生成→
   音声合成をすべて自分のサーバーで仲介する構成にしています。

2. **モデルにはツール（Web検索・画像生成・コード実行）を一切渡していません。**
   これにより「頼まれても物理的にできない」状態を作っています。トピック制限
   （宿題・雑学・プログラミング相談などを断る）はシステムプロンプト頼みの
   ソフトな制御なので、100%ではない前提で、モデレーションAPIと構造化出力
   （`off_topic_attempt` フラグ）を組み合わせて多層防御にしています。

3. **音声もログも既定では保存しません。** 受け取った音声はメモリ上で
   文字起こし処理をするだけで、ディスクや外部ストレージには書き込みません。
   会話の短期記憶（直近数ターン）もインメモリで、30分操作がないと自動的に消えます。

## 本番運用前にやるべきこと

- `src/lib/sessionStore.ts` / `src/lib/usageLimiter.ts` は単一プロセス前提の
  インメモリ実装です。複数インスタンスで動かす場合は Redis 等の共有ストアに置き換えてください。
- 13歳未満の子どもの個人データを扱う場合、OpenAI は API 利用規約上
  ゼロデータリテンション（ZDR）の設定を求めています。家庭内利用に閉じるのでない限り、
  OpenAI に確認・申請してください。
- 保護者ログイン（PINなど）を追加し、設定変更や利用時間のリセットを子どもが
  行えないようにすることを推奨します。
- モデル名（`CHAT_MODEL` / `TRANSCRIBE_MODEL` / `TTS_MODEL`）や Responses API の
  レスポンス形状は変化が速い領域です。デプロイ前に最新の OpenAI ドキュメントで
  確認してください。
