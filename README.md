# English Time! (MVP)

子ども向けの、音声だけで完結する英会話練習アプリの最小構成です。複数の子ども
プロフィールに対応しており、子どもは OpenAI / ChatGPT に一切触れず、常に自分の
バックエンド（この Next.js アプリの API Route）経由でのみ会話します。

## できること / できないこと（MVP時点）

- できる: マイクで話す → 文字起こし → システムプロンプトで応答生成 → 音声で再生、を繰り返す
- できる: 入力・出力の両方をモデレーションし、危険/範囲外の発言はやんわり英会話に誘導
- できる: 複数の子どもプロフィール（名前 + レベル1〜3）を保護者ダッシュボードから登録し、
  トップページの「だれとおはなしする?」画面で選択。利用時間・会話履歴・サマリーは
  子どもごとに完全に分かれて管理される
- できる: レベル（4-6歳ごろ/7-9歳ごろ/10-12歳ごろの3段階）に応じて、語彙・文の長さ・
  話題の広さを調整した会話（`src/lib/systemPrompt.ts` の `buildSystemPrompt`）
- できる: 1日あたりの簡易利用時間の上限（子どもごとにDBに保存、再起動しても保持）
- できる: 会話の短期記憶（直近8ターンのテキスト）をDBに保存
- できる: 保護者用PINゲート（`/parent`）と、そこから見られる子どもごとの今日の利用時間・
  会話サマリー・英検練習結果・範囲外発言ログのダッシュボード、子どもプロフィールの追加/削除
- できる: 英検3級 面接練習モード（パッセージ音読 → 内容質問 → イラスト説明・予測質問 →
  本人に関する質問2問、という実際の二次試験の流れをなぞった構成）。質問はすべて
  事前に用意した固定コンテンツ（`src/lib/eikenContent.ts`）で、面接中はモデル呼び出しなし。
  終了後にAIが講評（良かった点/次に試すこと）を生成し、`/parent` から確認できる
- まだ: フレーズ集計、音声の保存・会話ログの長期保存（意図的に未実装）、英検3級以外の級

## セットアップ

```bash
cp .env.local.example .env.local
# .env.local に OPENAI_API_KEY を設定
npm install
npm run dev
```

データは既定でローカルの SQLite ファイル（`data/app.db`、git 管理外）に保存されます。
外部アカウントは不要です。ホスティング先（Vercel など）で使う場合は、`.env.local` の
`DATABASE_URL`（`libsql://...`）と `DATABASE_AUTH_TOKEN` に Turso の値を設定するだけで、
コードの変更は要りません（`src/lib/db.ts` 参照）。

`http://localhost:3000` を開き、STARTボタンを押しっぱなしにして話し、離すと送信されます。

## 重要な設計判断（なぜこうしたか）

1. **ブラウザは OpenAI と直接通信しません。** OpenAI の Realtime API を
   ブラウザから WebRTC で直接叩く構成（エフェメラルトークン方式）も検討しましたが、
   その構成では接続後にクライアント側から `session.update` イベントを送ることで
   システムプロンプト（instructions）を上書きできてしまう、というのが現在の仕様です。
   子ども本人がそれをやることはまずありませんが、「子どもがChatGPT自体に触れない」
   という要件を技術的に保証するには不十分と判断し、MVPでは音声認識→テキスト生成→
   音声合成をすべて自分のサーバーで仲介する構成にしています。

2. **モデルにはツール（Web検索・画像生成・コード実行）を一切渡していません。**
   これにより「頼まれても物理的にできない」状態を作っています。トピック制限
   （宿題・雑学・プログラミング相談などを断る）はシステムプロンプト頼みの
   ソフトな制御なので、100%ではない前提で、モデレーションAPIと構造化出力
   （`off_topic_attempt` フラグ）を組み合わせて多層防御にしています。

3. **音声は保存せず、会話テキストも最小限しか残しません。** 受け取った音声はメモリ上で
   文字起こし処理をするだけで、ディスクや外部ストレージには書き込みません。
   会話の短期記憶として、セッションごとに直近8ターンのテキストだけを DB に保存します
   （それより古いターンは削除）。30分操作がないとその記憶は応答に使われなくなりますが、
   行そのものは DB に残る点に注意してください。
   インメモリではなく DB にしたのは、サーバーレス環境ではリクエストごとに別インスタンスに
   振られてメモリが共有されず、記憶や利用時間が失われるためです。

## 本番運用前にやるべきこと

- ローカルの SQLite ファイルは単一サーバー前提です。複数インスタンスやサーバーレスで
  動かす場合は Turso などホスト型の libSQL を使ってください。
- 13歳未満の子どもの個人データを扱う場合、OpenAI は API 利用規約上
  ゼロデータリテンション（ZDR）の設定を求めています。家庭内利用に閉じるのでない限り、
  OpenAI に確認・申請してください。
- `/parent` のPINゲートは `.env.local` の `PARENT_PIN` 一本で、家庭ごとに1つのPINという
  想定です（親ごとの個別アカウントはありません）。5回間違えると5分ロックされます。
- モデル名（`CHAT_MODEL` / `TRANSCRIBE_MODEL` / `TTS_MODEL`）や Responses API の
  レスポンス形状は変化が速い領域です。デプロイ前に最新の OpenAI ドキュメントで
  確認してください。
